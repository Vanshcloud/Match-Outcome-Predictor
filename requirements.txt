# Runtime dependencies.
#
# Canonical source of truth: pyproject.toml reads this file, and CI and the
# Dockerfiles install from it. Two lists of pins drift, and the one nobody
# installs from is always the wrong one.
#
# A dependency appears here with the code that first imports it, not in
# advance — an unused pin is a supply-chain surface with no upside, and it
# makes CI slower for nothing.

# ---- Configuration ----
# YAML defaults, .env overlay, validated into a frozen typed object.
PyYAML>=6.0
python-dotenv>=1.0
pydantic>=2.9

# ---- Data ----
# pandas is pinned below 3.0 deliberately. Unpinned it resolves to 3.0.x, which
# changes the default string dtype from `object` to `str` and makes
# Copy-on-Write permanent. Both are silent behaviour changes rather than
# errors — the worst kind in a pipeline whose whole job is reshaping frames.
# Revisit as a deliberate migration, not as a side effect of an install.
pandas>=2.2,<3
# Never imported by name. It is pandas' Parquet engine, and every canonical
# table this project writes round-trips through Parquet, so `read_parquet`
# fails without it. Listed explicitly because an implicit dependency is one
# nobody pins.
pyarrow>=17.0

# ---- Ratings ----
# numpy is listed even though pandas already pulls it in: src/ratings imports
# it by name, and a dependency you import is one you pin, not one you inherit.
numpy>=2.0,<3
# Dixon-Coles is a maximum-likelihood fit — two strengths per team plus a home
# term and the low-score correction — refitted every thirty days per
# competition. scipy.optimize.minimize (L-BFGS-B) is the whole reason this is
# a dependency. A second caller, minimize_scalar, is for the one
# temperature the calibration layer fits per fold.
scipy>=1.14

# ---- Storage ----
# The analytical store. Reads Parquet in place, so there is no load step and no
# second copy of the data — the aggregates this project asks for (coverage per
# competition, class balance per season) are column scans over the same bytes
# the modelling code reads. No server, no daemon, one wheel.
duckdb>=1.1

# ---- HTTP ----
# `requests` only. Every source this project reads serves CSV; no HTML parser
# is installed, because nothing here parses HTML. Playwright and Selenium are
# not used at all — the chosen provider serves static files.
requests>=2.32

# Declared because `src/utils/http.py` imports `urllib3.util.Retry` directly.
# It arrives anyway as a dependency of `requests`, which is exactly the problem:
# an import satisfied by somebody else's dependency is an import that breaks on
# the release where they drop it, with a traceback that names neither project.
# A direct import is a direct dependency.
urllib3>=2.0

# ---- Modelling ----
# Six model families are installed; what each is
# worth is measured in docs/MODELS.md rather than assumed here.
#
# scikit-learn covers three of them and, just as importantly, the imputer and
# scaler the other three do not need — so the choice to leave a null alone is
# made per family, in the open.
scikit-learn>=1.5
# The three boosted libraries. On macOS these need `brew install libomp`; the
# wheels link against it and fail at import without it, with a message about a
# missing dylib that says nothing about OpenMP.
xgboost>=2.1
lightgbm>=4.5
catboost>=1.2
# Hyperparameter search. Used on a slice of history that ends before the first
# reported fold, which is the only arrangement in which a tuned number means
# anything — see src/models/tuning.py.
optuna>=4.0
# Run tracking, to a local SQLite file under models/. Not a server: MLflow's
# own directory-based store is in maintenance mode and refuses writes in 3.x,
# and a tracking server is infrastructure this project does not want.
mlflow>=3.0

# ---- Explainability ----
# Only the tree explainer. It reads a boosted forest's own
# structure, which is exact and takes seconds; the general-purpose explainer
# that would cover the three pipeline-wrapped families costs hours for a number
# src/explainability/permutation.py produces exactly, for every family, from
# arithmetic that is already here.
#
# matplotlib is not installed. Every explainability figure would be a
# five-row table, and a PNG in a
# repository is a number that goes stale without a diff to show for it.
shap>=0.46

# ---- Serving ----
# The API. FastAPI's request models are pydantic, which is already here for the
# config, so the schemas and the OpenAPI document cost one dependency rather
# than three. `uvicorn[standard]` pulls httptools and uvloop; both are wheels
# and both are the difference between a demo and a server that can be measured.
fastapi>=0.115
uvicorn[standard]>=0.32
# The serialisation format for the fitted artefact. It ships with scikit-learn
# and is what scikit-learn's own documentation persists estimators with —
# listed explicitly because src/pipelines/serving.py imports it by name.
joblib>=1.4
# The served-prediction log. psycopg 3, no ORM: one table, created if absent,
# with every value bound. SQLAlchemy is deliberately not
# installed — see "No SQLAlchemy" in docs/history/MILESTONE_LOG.md.
psycopg[binary]>=3.2

# ---- Dashboard ----
# Streamlit renders the reporting tables the pipelines already produce and
# posts a fixture to the API for a live probability. It computes nothing: a
# second implementation of a metric is a second number to reconcile, which is
# the one thing a dashboard over a forecasting project must not add.
streamlit>=1.40
# Plotly rather than matplotlib, and the one exception to the note above: a reliability diagram is the one figure in this project that a
# table genuinely cannot replace — the diagonal is the claim being tested, and
# a reader checks a forecast against it by eye in a way no column of gaps
# supports. Interactive, so it is drawn in the browser rather than committed
# as a PNG that goes stale without a diff.
plotly>=5.24
